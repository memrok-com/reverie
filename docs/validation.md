# Validation and limits

The shipped package target is Pi 1.3.0 on Windows x64 with Node 24.9–24.x. Linux x64 development builds and native/Pi SDK tests run in CI; an installed Linux package and other Pi versions are not advertised as verified.

Native tests cover fictional chronology and fading, episode ownership, selective reflection and provenance, source mutation, cancellation, restart, invalid reflection, atomic publication, and model-independent deletion invalidation. Pi integration tests exercise its actual SDK, append-only sessions and extension runtime with a deterministic model and the native engine.

The terminal smoke and package smoke are recorded separately. A passing SDK test is not a substitute for checking shortcut dispatch and visible controls in an actual Pi terminal.

`scripts/pi-memory-wire-smoke.mjs` also exercises the packaged extension through a real Pi CLI and a credential-free OpenAI-compatible HTTP fixture. `validation/pi-memory-wire.json` records that empty recall adds no notice, actual recollections have the system role, and the player's unchanged message stays last. This check uses no real character data or external model.

The checked-in reports are historical Windows release evidence: `validation/native-tests.xml` (35 native/process acceptance tests), `validation/pi-tests.xml` (25 Pi acceptance tests), `validation/pi-package-smoke.json` (relocated archive and package installation), `validation/pi-terminal.json` (installed terminal interaction), and `validation/pi-installed.json` (registration in the existing user Pi installation). They do not describe the latest development test count. CI emits fresh reports under ignored `.work/ci-validation`; `REVERIE_VALIDATION_DIR` selects a separate evidence directory for local runs. Three Rust unit tests also run. The Pi suite includes real compaction entries, append-only message edits, persisted recall provenance, retries after failed/interrupted first generations, and saved per-folder model choices across reload/new sessions/restart. Missing-model tests verify that input and continuation paths do not reach a fallback provider. Provider-facing context tests verify empty recall produces no placeholder, real recall appears only in system context, the latest user message stays last, and memory does not accumulate or enter played source.

Issue #1 checks complete inspection beyond recall budgets and detail fading, future-memory isolation, source authorship and literal dialogue, empty/stale/unavailable/invalidated states, correction preview/cancel/application, historical reply explanations, durable corrected recollections across forced rebuilds and restart, source/prefix change guards, character isolation, adjacent episode boundaries, and migration of existing version-1 databases. Pi browser/editor flows run through the real SDK and native engine with deterministic reflection. The existing manual terminal report predates these new browser controls; their new coverage is automated SDK integration, not a fresh manual terminal session.

Story backup checks cover selected alternatives and internal fork ancestry after relocation, reviewed corrections and withdrawn episodes, source ownership/provenance, unavailable models, rebuilding from restored play, archive integrity and collisions, rollback on publication errors, and recovery of incomplete/complete/truncated journals. Held ownership locks and simulated PID reuse check concurrent recovery. Export tests verify that source I/O permits unrelated database writers and that a changed story cannot publish a mixed snapshot. These are controlled filesystem/database/SDK tests; real power loss has not been simulated.

Issue #3 checks cover relative anchor boundaries, duplicate-label selection, resolved-date previews, gap creation and cancellation, full-interval overlap rejection, re-date dependency and correction previews, stale revisions and token isolation, migration from version-2 databases without resampling, canonical rebuild order and future-memory isolation. Real Pi SDK tests preserve transcripts, selected leaves and time-jump spacing through repeated shifts, new time entries, branch navigation and restart. Backup round trips preserve chronology offsets; older archives import with zero offsets. These controls have automated coverage; the historical manual terminal report predates the grouped menu and re-date controls.

The PR #24 review regression reproduces an unselected branch ending January 10 while the selected branch ends January 2: moving the episode from January 1 to January 25 must reject its translated February 3 extent against a February 1 neighbour. Native and real Pi SDK regressions fail against the original PR implementation. Pi checks both active and saved episodes, then verifies a valid move retains the selected branch and lets the longer alternative resume and play after restart. Additional checks cover offset-adjusted branch bounds, a branch date changed during confirmation without a native revision change, and readable sub-day shift units.

A second review regression corrects an episode's setup date from 2020 to 2000 before play, advances to January 3, and places a neighbour in 2010. It fails against `25a93b4`, where the abandoned setup date falsely extends the interval to 2020. Real Pi SDK coverage now verifies successful re-dating from saved and active sessions, unchanged entries/selected source, and continued play after restart. Tree-based unit checks retain longer alternate tips, ignore superseded ancestor dates, handle offset-adjusted times and unordered entries, and reject incomplete or cyclic trees. The earlier alternative-branch overlap regression remains in the suite.

The remaining interior-setup edge is exercised by selecting the superseded 2020 entry in Pi's actual history tree after playing in 2000, with a neighbour in 2010. Date restoration fails as before; re-dating now detects the selected/native time mismatch and offers recovery guidance before any date or memory changes. Active and saved-source regressions verify unchanged native revision/intervals, zero model calls, and successful re-dating after returning to a valid branch. Against `f2d31f4`, the saved-source case accepts the move and the active case produces only the later overlap error. Tree navigation's existing overlap rejection remains unchanged.

The quality of remembered prose remains model-dependent. Retrieval uses lexical matching with reflected cue words, recency and emotional salience; there is no embedding model or inference call during retrieval. Reflection requires the full selected episode to fit the configured model context. Reflection can fail safely on invalid or overlong output.

Issue #22 integration checks run through the real Pi SDK and native engine. They distinguish unchanged ordinary repair after model/thinking changes from confirmed full regeneration, check the previewed model route and included episode count, preserve the captured route across a Pi model change during confirmation, and keep withdrawn episodes excluded. Cancellation before work makes no model calls. Cancellation or model failure in the second episode leaves even the already-staged first episode unpublished. Other checks cover empty scope, changed scope during confirmation, exact preservation of reviewed recollections and correction durability after restart. Review regression coverage lists multiple later corrected episodes with inspection commands and release guidance before confirmation, verifies zero model calls and unchanged published memory/corrections, and permits the first included correction despite earlier unplayed or withdrawn corrected episodes. These controls have automated SDK coverage; no new manual terminal verification is claimed.

Recall-history tests compare identical played scenes with and without per-turn recall associations. They verify the shifted-topic context, original-source provenance, first/latest associations, current-message citations and absence of duplicate old events through deterministic reflection fixtures. Other checks cover recency/salience selection, strict Unicode budgets, uncertainty, branch alternatives, failed generations, restart, relocation through backup, source edits, fictional time, cross-character exclusion and invalidation after correction/withdrawal/deletion/rebuilding. These are context-contract comparisons, not measured prose-quality gains on live models. No reinforcement mechanism is enabled. See [comparison cases and limitations](recall-history-evaluation.md).

Review regressions use real Pi session files, the catalog/service and the native engine to delete later episodes and verify unchanged earlier recall records, contribution hashes, ongoing context and zero extra model calls on rebuild or memorization. They cover integrated/external deletion, affected later histories, other characters, unmemorized drafts, adjacent interval endpoints, changed current/published dates, repeated acknowledgment, chronology changes after planning, and restart between native deletion and catalog cleanup. Both preservation regressions were also run against the pre-fix catalog/service and failed with missing earlier recall records. Native tests distinguish identical-prose recollections by stored ordinal across restart/republication and verify that reflection history omits engine-only fields and raw background source IDs. A reordered-archive restore test also checks that identical-prose memory indices and provenance survive new row-ID allocation.

Withdraw-then-delete and invalidation-before-delete regressions check that removed memory prose disappears from both saved explanations and decoded story ZIPs. The withdrawal regression also fails against `88cb62c`, retaining the deleted memory gist in the surviving reply. Reference coverage includes fresh memories, historical context, impression/shared-history sources and re-dated episodes, while unrelated replies in the same episode and other characters survive. Current and legacy cleanup-plan recovery, contexts written after planning and rejected late writes after deletion are also exercised.

The impression-author regression uses a real native reflection with no individual memories and an impression citing only an earlier episode. Retrieval supplies that impression without another reference to its author. The test failed at `2dc3ad0` because withdrawal followed by deletion retained the impression in a saved reply. It now checks physical row removal for a known snapshot owner and absence from every decoded backup ZIP member. A legacy record without the new owner field instead loses only its ambiguous impression prose and rendered copy, preserving unrelated recollection associations. Additional checks cover snapshot-owner cleanup plans across restart, contexts arriving after planning, rejected late writes and their diagnostic counter, and the character-scoped conservative fallback for legacy impressions. Deleting a draft after legacy redaction still rebuilds with zero reflections and preserves the earlier published contribution.

A separate live comparison on 2026-10-29 used `openai/gpt-6.1-sol` with medium thinking: eight calls across two authored scenes and baseline/history conditions, with all four reflections accepted by native validation on the first attempt. Both conditions preserved current-event citations and the distinction between suspicion and witnessed events. The tiny sample showed no clear prose-quality or continuity gain; history-condition impressions were less explicit about cross-episode links. [Raw live evidence](../validation/recall-history-live.json) and the [assessment](recall-history-evaluation.md) are included without a sustained-play quality claim.

Reply alternatives are branches. Only the selected history is memorized. Rejected branches remain in Pi's file until the whole chat is deleted. Branch changes after memorization require memorizing again. Later derivatives of a deleted episode are withheld until rebuilt; deletion never waits for a successful model call.
